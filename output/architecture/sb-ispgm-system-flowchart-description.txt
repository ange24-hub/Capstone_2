System Flowchart

The system flowchart illustrates the overall sequence of activities in the developed SB-ISPGM system. The user opens the system and either signs in with an existing account or completes the registration process available to residents and barangay secretaries. A successful registration creates a pending account and signs the user in automatically. Existing users enter their email address or user ID and password. Invalid credentials return the user to the login form for another attempt, while valid credentials establish an authenticated session.

The system checks whether the account is approved or belongs to a Municipal DILG user. Unapproved resident and secretary accounts are directed to an account-status page and cannot access protected services. Resident applications are reviewed by barangay secretaries, while secretary applications are reviewed by Municipal DILG users. Municipal DILG accounts are provisioned separately from public registration. Authorized users are directed to the dashboard corresponding to their role.

Residents can submit document requests and payment evidence, communicate concerns, and track their transactions. Barangay secretaries can review resident applications, maintain household, RBI and migration records, process requests and payment evidence, respond to concerns, and access authorized reports, maps and forecasts. Municipal DILG users can review secretary applications, manage barangay configuration, and access authorized municipal summaries, RBI reports, maps and forecasts. These activities represent alternative menu choices rather than a mandatory sequence.

For each selected task, the system checks permissions, record scope and submitted information. If the request is not permitted or the input is invalid, an error is displayed and the user can return to the appropriate dashboard to correct the information or choose another task. Otherwise, the system executes the operation, reads or updates records as needed, and displays the resulting status, report or output. Migration forecasts depend on sufficient verified monthly history; where eligibility requirements are not met, the system displays the relevant data limitation.

After viewing the result, the user may perform another task or log out. Connector A indicates a return to role-based dashboard selection. Logging out invalidates the session and ends the workflow. Ovals indicate start and end points, rectangles indicate actions, diamonds indicate decisions, and parallelograms indicate input or output. The chart summarizes normal system use; detailed registration validation, password recovery, offline capture, and specialist service workflows are outside this overview.
