# One-time BRBI append-only online sync

This release transfers the user's existing November 8 BRBI archive data into the existing online database. It does not replace that database, seed accounts, delete demo records, fabricate migration events, or guess reporting dates.

The container creates a dedicated RSA-3072 recipient key inside private persistent storage. The HTTPS GET `/api/deployment-data-sync/brbi-20261108` publishes only the public key and aggregate progress. It cannot accept uploads or initiate any command. The private key is never exported. Local preparation encrypts the reviewed source plan with a random AES-256-GCM key wrapped using RSA-OAEP. The ciphertext is bound to the recipient key, fixed release and production hostname. Only the intended online container can decrypt it. Neither resident plaintext, APP_KEY nor passwords go into the release repository.

`scripts/prepare_encrypted_brbi_sync.php` reads the original private archive and an HTTPS-fetched recipient public key. It exports six previously missing consolidated barangay registries and all 29 barangays' NEW worksheet rows. Recipient barangay IDs are resolved by name. Original worksheet provenance and missing dates are retained. Whole workbooks and local database dumps are not transported.

On deployment, `brbi:sync-release` applies the reviewed encrypted resource only in production at the fixed online hostname. It locks and backs up all ten affected tables privately, appends only missing identities, prepares unsigned missing RBI draft rows, and verifies all old records by hashes. Submitted forms remain byte-for-byte unchanged; old draft rows remain an exact prefix and only their rows/update timestamp may grow. Name collisions with missing or conflicting identity information are held for review. Existing residents, their household fields, signatures, classifications, migrations, and existing form members cannot be overwritten or removed. Verification failure rolls the transaction back. The website remains available if the sync fails.

Private backups, detailed identity review and diagnostics are under `storage/app/deployment-data-sync/`. The public report contains only aggregate counts and completion/preservation status. A completed envelope is not reapplied on ordinary restarts; identity checks also make a retry idempotent. After completion the encrypted resource may be removed from the branch. Keep private backups for recovery. A database restore performed independently of storage requires a fresh review of the completion marker before syncing again.
